# Rust/C++ Wasm and WebGPU feasibility results

Date: 2026-10-19 (Australia/Sydney)
Engine revision at baseline: f69999f4
Scope: implementation-plan Task 1 only. No engine renderer, scripting architecture or publishing behavior was changed.

## Outcome

Both feasibility gates pass: C++ and Rust execute in the same browser Wasm module, and C++ renders a correctly textured sprite through WebGPU using Slang-generated WGSL on a hardware adapter. A separate representative C++/Box2D browser probe also passes.

Reproduction entry point: tools/experiments/rust-webgpu/Run-Feasibility.ps1. Prerequisites and exact invocation are in that directory's README.md. The runner installs nothing, enforces tested compiler versions, bounds each stage, terminates timed-out child processes and returns a nonzero exit code plus a failed JSON report on failure.

The layout probe exchanges a repr(C) record with a u32 tag, u64 entity value, pointer and size_t length. Both languages verify field values, not only sizeof.

| Layout property | Windows native | Wasm32 |
| --- | --- | --- |
| Pointer bytes | 8 | 4 |
| Record bytes | 32 | 24 |
| Record alignment | 8 | 8 |
| Entity offset | 8 | 8 |
| Pointer offset | 16 | 16 |
| Length offset | 24 | 20 |

This directly demonstrates why pointer-bearing ABI structures cannot be serialized as portable data. Caller-owned output buffers avoid cross-allocator ownership. UTF-8 and callback checks passed with the rebuilt Rust std. A Node run of the same Wasm also passed, but browser qualification relies on actual Chrome execution.

The C++ library probe executes std::expected, std::format, std::span, a PMR vector, a coroutine and lexical std::filesystem path operations under the Emscripten C++26 mode. It does not prove OS filesystem access, threads, all engine headers or every C++26 facility. Box2D was compiled from existing dependency sources into a separate artifact tree; third-party sources were not modified.

## Baseline and limitations

The existing ./scripts/Run-DebugGauntlet.ps1 -Fast run completed in full mode: GPU abstraction guard, Editor/GameRuntime/EngineTests build, 1,347 native test cases, editor smoke and runtime smoke all passed. Both smokes reported zero validation findings. The build portion took 251 seconds on the existing tree.

Separately invoking the managed SDK tests found 131 passed and 29 failed out of 160. A representative existing NetSessionDirector test fails with DllNotFoundException for AetherHost when setting EulerDegrees. This was reproduced without experiment integration; no existing managed source was changed. The standalone managed baseline is not green and must remain distinct from the passing native gauntlet and feasibility suite. Logs: logs/rust-webgpu/managed-baseline.log and managed-baseline-detail.log.

Initial Rust std compilation took about 40 seconds. One warmed GPU case reported about 216 ms from page initialization through readback completion. The initial interop Wasm was 69,377 bytes. These are individual observations, not performance budgets or comparative claims. Current sizes, hashes, browser timings and build-stage durations are recorded by each aggregate run; generated debug/assertion flags are part of those measurements.

One browser integration defect was caught and fixed: an HTML lexical Module declaration collided with Emscripten's generated Module declaration. The loader now uses a compatible var declaration. Negative shader/adapter tests verify that startup or validation failures cannot masquerade as rendering success.

## Consequences for the next milestone

Proceed to the shared gameplay contract with this pinned ABI combination as an executable reference. Do not merge the experimental structs directly into a public engine ABI: freeze sizes/version negotiation, ownership, world/handle validation and diagnostics in Task 2.

The WebGPU proof validates explicit uniform/storage bindings, a sampled texture and asynchronous completion. It does not translate AetherCore's buffer-device-address/bindless shaders, port the render graph, establish engine-wide exception behavior, deliver a browser game runtime or implement a Rust gameplay host. Those remain subsequent plan tasks.

Retain Vulkan and desktop C#. Rust browser export remains first, C# browser export follows. Broad GPU/browser qualification and real hosted itch.io embedding remain separate acceptance gates.
